# DR-009: Reframe to the contract, before the fix batch locks in

**Date:** September 26, 2026

## Why this memo now

The mechanism is confirmed and the fix batch is pre-registered — good. But the evidence and the fix are aimed one level too shallow. The bug isn't "mlx5 parks." It's that **NAPI's poll-return value carries two conflicting signals — how much work was done, and whether the core should keep polling here — and threaded NAPI makes them conflict.** Fixing that framing before the batch runs is the difference between a driver-bug paper and a contract-defect paper. Three changes, none needing new hardware.

## The contract, stated precisely (put this in the paper)

In `net/core/dev.c`, `__napi_poll` (v6.17.8, line ~7542):

- `if (likely(work < weight)) return work;` — any return **below** budget tells the core "done, don't repoll."
- Only `work == weight` sets `*repoll = true`.

The driver detour (`mlx5e_napi_poll`, and the same idiom in mlx4/i40e/iavf/gve) does `if (done == budget) done--;` — it **deliberately underreports work** to land in the `work < weight` branch and stop the poll, so the interrupt can restart it on the right CPU. Under softirq NAPI that was harmless. Under threaded NAPI the thread is already off-CPU by scheduler choice, the restart assumption is void, and returning `budget-1` strands the pending backlog with no repoll and no re-trigger.

**The defect is the overloaded return value.** Everything below tests and fixes that, not the driver.

## Change 1 — E7 first (was queued behind E3). Highest priority.

The empty minimization intersection means threaded=0 latches exist (069, 038, 089). Decide whether they are the **same contract bug via a different trigger**.

- Recreate 069's config. Wedge it (threaded=0, softirq NAPI).
- Trace the poll path: does an IRQ-affinity move (irqbalance-style, the exact 2017 case) land the **softirq** poll off its channel's CPU, hit the same `done--` detour, return `budget-1`, and strand the backlog?
- **If yes:** one contract defect, two triggers (scheduler placement under threaded; affinity move under softirq). The paper unifies. This is the result we want.
- **If no:** characterize the second path; the paper must report it honestly as distinct.

Deliverable: an AN addendum with the threaded=0 poll trace and the verdict. Nothing else proceeds to disclosure until this is known — maintainers will ask "is the default-kernel latch the same bug?"

## Change 2 — Instrument the contract, not just the outcome

The fix spec's F1 gate is currently "BASE-vs-F1 delta on dead cells." Replace it with a **structural** gate that observes the contract violation directly.

- Add a logger on `trace_napi_poll` (already fires in `__napi_poll` with `work, weight`) plus, per poll: the CPU, whether the CPU is in the channel's `aff_mask`, and the channel's CQ backlog (producer − consumer).
- Define the **stranded-backlog event**: `work < weight` AND `repoll` not set AND `backlog > 0` on an off-mask poll.
- **This event count is the metric for the whole paper.** BASE shows it firing continuously on a wedged queue; a correct fix drives it to zero. Report it for BASE and every fix arm.

This converts "our fix reduced dead cells" into "our fix eliminated the contract violation, observed at the core." That is the OSDI-grade evidence.

## Change 3 — Add F3, the fix that repairs the contract

F1 and F2 both dodge the defect: F1 refuses to honor the detour (abandons placement), F2 pins the kthread (removes threaded NAPI's whole point). Keep both as the "naive fixes" comparison, and add:

- **F3 (contract fix):** on a budget-exhausted off-mask poll, return **`budget`** (so the core's repoll is honored and the backlog is not stranded), and express the placement preference through the channel the core already tracks — request the repoll on `napi->config->affinity_mask` rather than encoding it in the work count. Verify the `napi_config`/affinity-mask layout in the build tree before compiling.

Pre-register F3's four predictions:
1. PROBE-DEAD 0/8 (like F1/F2).
2. The stranded-backlog event count → 0 (unlike BASE).
3. The poll **migrates**: within one repoll, polling lands on the affinity CPU and `aff_change` returns to ~0 — i.e. placement is preserved, not abandoned (F1) or frozen (F2).
4. Livelock check passes (≤5% goodput degradation in the threaded=0, app-on-IRQ-core, 525k config), and no busy-poll/XSK regression.

If F3 hits all four, it's the paper's fix and F1/F2 are the foil. If F3 can't satisfy 3 and 4 together, that tension is itself a finding — report it.
