# DR-008: Experiments to close the mechanism and the class

**Source findings already established (do not re-run, but cite):** threaded NAPI threads are created unpinned; mlx5 does not opt into core affinity automation; the NAPI docs' busy-poll advice points at an off-IRQ core; five drivers share the idiom with divergent restart strategies. Your experiments now *confirm on hardware* what the source predicts, and settle severity and novelty.

**In-flight, let them finish:** PERSIST (A0–A8), rxfuzz minimization.

### E1 — Fresh-boot default-pinning check (5 min, highest value)
Fresh boot. `echo 1 > /sys/class/net/enp195s0np0/threaded`. Before touching anything, read every `napi/enp195s0np0-*` thread's `/proc/<pid>/status` `Cpus_allowed_list`. **Predict (from source): 0-63 (unpinned).** If unpinned → default exposure, and the disclosure says so. Record once; it's a headline fact.

### E2 — Verified-aligned re-run (closes the invalid Sept-24 test)
The earlier "refutation" failed its manipulation check (`aff_change` 598–1065/s in the aligned arms). Re-run aligned (thread pinned to CPU 8, IRQ 312 on CPU 8), logging **per second**: the thread's `Cpus_allowed_list`, `/proc/irq/312/effective_affinity_list`, and `ch7_aff_change` delta. A cell counts only if `aff_change`≈0 throughout. **Predict: 0 wedges.** This is the clean confirmation the affinity detour is the cause. Add the addendum to AN-003 noting the earlier test's control failed.

### E3 — i40e on Clemson c6420 (the class test, discriminating)
Request c6420 now. Pre-register from source: i40e forces an interrupt after bailout, so **predict: repeated bailout+interrupt, throughput loss, but NO trickle and NO latch.** If i40e latches anyway → the restart-strategy theory is wrong; escalate. Same overload harness, `ethtool -S` for the i40e force-wb counters.

### E4 — mlx4 if ConnectX-3 exists on CloudLab (strongest class confirmation)
Check the CloudLab hardware list for any ConnectX-3 node. mlx4 waits like mlx5. **Predict: same latch as mlx5.** A second *latching* driver, predicted from source before running, is the paper's spine. If no CX-3 node exists, note it as a limitation.

### E5 — The fix, built and measured
Two variants, both against the running v6.17.8:
(a) driver-local: force a re-trigger on every affinity bailout (as mlx5 already does for XSK, i40e always);
(b) core: pin the threaded kthread to `napi->config->affinity_mask`.
**Success:** the trickle/latch disappears **and** the original 2017 livelock (interrupt stuck on a pegged CPU) does not return. Measure both goodput-under-overload and the livelock case the bailout was written for.

### E6 — lore.kernel.org novelty search (desk)
Search lore for: `mlx5e_channel_no_affinity_change`, `aff_change threaded`, `threaded napi affinity stall`, `napi thread wrong cpu poll`. Record hits or "none". Closes the novelty gate for disclosure.

### E7 — The two threaded=0 fuzz hits (069, 089)
Minimize + one trace. With softirq NAPI there should be no detour, so these are either rxfuzz's mid-cell IRQ-affinity perturbation (the 2017 case) or a second mechanism. Classify before any generality claim.
